# 全文语义说话人复核

review-prepare将每篇完整原文写到`review/packets/ID.json`，queue只列路径和字符数。每篇按顺序读完所有segments；char_start/char_end是原文全局偏移，范围左闭右开。ASR段可能跨多个说话人，不能仅按segments切人。

判别主播的追问、分析、建议及连麦者的处境、回应、反驳。主播第一人称举例、读投稿、模仿及引用不新增真实参与者；来电者讲配偶原话仍属来电者。片头预告与正文相同处对照判断。多方真实交替可用连麦者（妻子）/（丈夫）/（男生）/（女生）；未知性别不强加标签。

输出一个JSON对象，每个视频ID一个记录：
```json
{"视频ID":{"source_sha256":"packet中的哈希","reviewed_full_text":true,"mode":"对话","_boundaries":[[0,"主播"],[18,"连麦者"],[90,"不确定"]],"review_note":"全文阅读后的具体判断依据；仅语义，未听校。","uncertain_reasons":{"90":"这一残句可能是剪辑旁白或来电者插话，文本没有足够承接。"}}}
```
边界必须逐字定位，不修改错字，不补台词；reviewed_full_text只能在确已通读时填写true。每个不确定起点分别有原因，不能只写“低置信”。不要把缺失的音频证据虚构成已听到音色。

可使用长上下文原文锚点定位，切勿直接搜索“有”“是”“想过”并取第一个命中；先确定问句末尾和回答的完整位置。片头/正文重复锚点需要明确出现次数。提交前检查边界附近完整问句、短答及词尾。

仅返回边界，不输出整篇重写稿。review-apply检查SHA/合法角色/边界和原因，全批结构验证通过才应用；不合法时修对应项，不重读无关稿件。相同accepted记录复用，不重复生成。程序不能证明助手确实阅读或语义正确，这由执行者负责。

若原文疑似错误导致归属无法确认，保留原文，给疑点原因和时间；需要听校时播放对应本地音频再独立记录修订，不用推理编造“更通顺”原话。

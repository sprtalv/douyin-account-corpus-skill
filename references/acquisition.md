# 正常浏览器采集适配

不假设某个平台或某个浏览器工具永远存在。先发现当前工具能力并读取其文档；优先正常页面操作，能力不足时说明缺口，不使用未授权接口或绕过登录、验证码、DRM。

1. 打开用户给定主页，记录实际账号URL、名称、可见作品数、日期及页面证据。视频、图文、直播回放分别记录，不将图文计入成功音频转写。
2. 滚动时逐屏累积已观察作品ID、标题和视频URL；虚拟列表最后一屏不代表整个主页。置顶以ID去重，直到多轮无新增；与可见数对比，不把停止条件当全量证明。
3. 保存JSON清单，import-index。无法解释的数量差异记录到`sources/coverage.md`，说明当时可见范围，不伪造已删除历史。
4. 正常打开/播放视频。只有当前工具允许读取播放器公开媒体信息或网络响应时，才获取音轨URL；明确绑定当前视频ID与页面。不得通过后门接口、挑战签名构造来绕过限制。
5. 少量观察立即导入observe并run，减少URL过期；3—5个真实代表样本先验证来源/时长/原文映射再扩大批量。工具无法合法取得媒体时使用用户合法本地文件或已有字幕。
6. 不要求用户交出Cookie。若浏览器需要本人登录，交还用户操作；记录受限条目并继续可处理部分。

本技能不捆绑平台私有接口爬虫。可按当前授权使用浏览器工具或本地浏览器脚本采集公开页面；Python接收已观察数据并处理。普通HTTP只返回脚本外壳时，不等于必须逐条桌面操作，先验证正常渲染浏览器路径。

## blob播放器与独立音轨（真实采集修补）

当已有成功项目时，先读其采集日志和一份媒体元数据，复用被验证的获取方式；不要把旧账号数据导入新账号。

- `video.currentSrc`为`blob:`是播放方式，不是访问被拒的证据。`downloadMedia`不支持blob，也不代表没有公开音轨。
- 如果当前浏览器提供`pageAssets`，先读其能力文档，再调用`list()`检查**全部分类**。抖音分离音轨可能分类为`other`，名称/URL包含`media-audio-und-mp4a`；视频轨可能包含`media-video-avc1`或`media-video-hvc1`。不要仅筛选`kind === 'video'`，也不要因`bundle`不支持other就判定无法下载。
- 只使用这次正常播放时资源清单实际返回的完整HTTPS音轨URL，不拼接、推导签名，不读取Cookie或应用隐藏状态。把观察到的URL交给本地下载器即可；优先独立音轨，通常无需下载视频。
- 复用标签后资源清单可能漏掉已缓存的音轨。先等页面可见标题、作者和播放器加载；仍无音轨时为该已知作品新建正常标签，读取清单后关闭。失败有界，保留具体失败原因，不因单条失败中止其他账号。
- 独立作品页通常更容易绑定音轨：核对最终URL的视频ID、可见标题、作者主页链接；若跳到推荐流，不得把推荐视频音轨归给请求ID。一个页面存在多个音轨且无法明确关联时，不按资源顺序猜测。
- 链接可能附查询参数：通过URL的pathname解析`/video/<19位ID>`，不要直接取字符串最后一段连查询参数一起作ID；保留原始链接作为证据。
- 采集少量即入队下载，正常页面采集继续推进，本地单GPU串行消费，避免等全部账号枚举完才下载导致URL失效。用户已指定全量时，样本通过后持续扩大，不再次停在样本等待确认。

下载时使用已核验作品页作为Referer以及常规User-Agent。401/403可能是过期或访问限制，应回正常页面重新观察，不无限重试，不绕过验证。保留响应状态、大小、音轨时长和SHA256。

### 桌面控制恢复后的已验证替代入口

浏览器资源接口不可用、但当前官方桌面控制可正常操作时，可通过正常浏览器开发工具的网络面板观察公开媒体请求。只读取页面播放产生的独立音轨地址，不执行控制台脚本，不保存Cookie、认证请求或整份含敏感字段的网络日志。独立作品页的最终URL、可见作者及播放时长必须核对；同一音轨的多次分段请求按完整URL去重，多条不同音轨仍不得猜测。

桌面工具的set_value可能只改变筛选框显示值而不触发筛选。若显示筛选词但请求列表仍包含全部脚本，使用正常点击、全选、键盘输入，并刷新可见状态验证筛选生效。输入/导航后的首次状态可能仍是旧页面，须等新页面的文档URL与标题真正出现。窗口最小化时使用官方窗口激活接口；工具明确因网址验证或策略停止时停止本轮UI操作，不绕过限制。

## 存储清理与结果核验

用户要求节省空间时优先只下载独立音频。必须下载视频时，先提取音轨并校验时长；转写、原文和来源映射验证通过后删除临时视频。复核需要的紧凑音频暂留；空间不足时只清理已完成且不再需要回听的媒体，记录原始SHA256、字节数、删除时间及原因。

不能直接删除数据库仍绑定的媒体，或把替代音频冒充原始媒体哈希。清理已绑定源前保存保留/派生记录，明确解除源路径绑定，保留原始源哈希和文字；派生音频单独记录路径及哈希。清理后运行完整性验证。当前CLI没有通用cleanup命令，需要任务级安全清理实现；不宣称run会自动清理。

补充实测：部分短作品只有含音视频的公开媒体请求，没有独立 media-audio。只在独立作品页的作者、最终作品 URL 都已核实，且媒体请求本身明确带有匹配的 __vid 时，才将该请求交给本地提取音轨；多个无法绑定的请求不猜测。保留视频源与派生音频各自的哈希，文字验证后清理临时视频。

Edge 打开网络面板优先使用 Ctrl+Shift+I；F12 可能弹出额外提示。关闭普通提示使用观察到的按钮或关闭图标。本环境的 Escape 可能触发 Computer Use 停止，工具一旦报告停止，本轮立即停止 UI 操作，不能用其他控制方式绕过。

## 本地浏览器脚本（2026-11-17 实测）

用户授权本地自动采集时，可用 Playwright 启动独立的本地 Edge headless 实例，通过渲染后的 DOM 读取主页及作品页，通过页面实际发出的公开媒体请求取得音轨。无需付费插件，不复制个人浏览器配置或 Cookie，不连接私有调试会话，不构造平台签名；遇到登录/验证码记录受限并跳过。

先验证少量真实媒体的账号、作品、时长、转写与清理闭环，再直接启动已授权全量。逐条页面由脚本导航，不需要助手逐条鼠标操作。主页必须处理内部滚动容器，保存逐轮去重清单、可见总数、图文数及到尾证据；停在首屏不可报告全量。已有成功稿跳过，单条失败继续其他条目。

任务级采集器应与下载转写服务连接，小队列背压避免签名URL过期；持久化采集状态和具体失败原因，监控必须区分进程运行、队列空闲和全量完成。当前任务的实现位于 accounts-19/browser_collect.py，依赖该任务收件箱服务，不是通用安装包。进度监控按用户要求每300秒执行；磁盘保护可维持更短间隔。正文保存验证后清视频，音频按空间阈值有记录地清理。
